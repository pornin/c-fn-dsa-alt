# FN-DSA (in C), Alternate RAM-Efficient Implementation

FN-DSA is a new *upcoming* post-quantum signature scheme, currently
being defined by NIST as part of their [Post-Quantum Cryptography
Standardization](https://csrc.nist.gov/pqc-standardization) project.
FN-DSA is based on the [Falcon](https://falcon-sign.info/) scheme.

**WARNING:** This code is based on the
[*c-fn-dsa*](https://github.com/pornin/c-fn-dsa) implementation. It is
an *alternate implementation* which is RAM-efficient (RAM usage is
divided by about 3) with comparable CPU efficiency (it is somewhat
slower on large CPU, and somewhat faster on Arm Cortex M4). Like
*c-fn-dsa*, it tries to follow what is my *best guess* at what the
upcoming FIPS 206 draft will contain. Exactly when that draft will be
published is not known. Moreover, the *c-fn-dsa-alt* implementation uses
a different sequence of floating-point operations (and fewer such
operations), so that it *cannot* always reproduce test vectors with a
given seed; for practical security reasons explained in the paper, I
actually changed the inner randomness hedging so that it now *never*
reproduces the test vectors. It is nonetheless as safe as the original
(arguably, even slightly safer), and fully interoperable (the same
private key, public key and signature formats are used, keys generated
by one code can be used by the other, and signatures generated by one
code are verifiable by the other).

API is the same as *c-fn-dsa*; usage is unchanged.

The [paper](tex/fndsa-small-ram.pdf) explains the used methods (the
paper has also been submitted to [ePrint](https://eprint.iacr.org) and
should be available there in a few days).
